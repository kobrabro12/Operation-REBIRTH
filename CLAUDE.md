# Operation REBIRTH — notes for Claude

Read this first. It replaces exploring the repo. Only open the files a task actually touches.
Game rules and numbers: `DESIGN.md`. Recipes: `.claude/skills/` (add-fighter, add-stage, add-item).

## What it is
2D pixel-art platform fighter (Smash-style) for the browser. Up to 4 fighters, CPUs fill empty slots.
Keyboard + gamepad + touch. Stages float in the sky with hazards; items drop mid-match. Stock and Stamina modes.
Owner: Mason (artist; does the sprites and design). Live build: https://kobrabro12.github.io/Operation-REBIRTH/

## Stack
- **Phaser 4.2.1** loaded from CDN in `index.html` (global `Phaser`, not imported). Vite 6 for dev/build.
- Plain ES modules, no TypeScript, no framework.
- `npm run dev` → http://localhost:5173. `npm run build` → `dist/`.
- Every push to `main` auto-deploys to GitHub Pages (`.github/workflows/deploy-pages.yml`). Treat `main` as live.

## Core rules (from `src/config.js`)
- 640×360 view, fixed 60 fps step. **All speeds are pixels per frame**, all timings are frames.
- `PHYS`: gravity 0.42, maxFall 6.5, fastFall 9.5, hitstun = 4 frames per unit of knockback, tumble above kb 6.
- Blast zones: x ±600, top −380, bottom 320. Coordinates centred on the stage, +y is down.
- Knockback = `base + growth * (target % after hit) / 100`. Angle 0 = forward, 90 = up, >90 = backward, <0 = down.
- Limit gauge fills to 100 from damage taken, then O fires the fighter's Limit super.
- CPU difficulty table: `DIFFICULTY` in config.js.

- **Soul Summoner and Mr Wake animations** are built from Mason's idle drawings cut into real limbs (`tools/sprites/ss_rig.py`, `mw_rig.py`, shared helpers `biped.py`: hidden-pixel fills, joint caps, leg IK, poses by limb direction). Moves, jump and fall come from `soul_summoner_moves.py` / `mr_wake_moves.py`; their idle and run sheets are Mason's hand-made ones.
- **Mr Wake** (`mr-wake`, keys `wake_*`): 176×120 move frames. Rosebud costume.
- **Lacy / Hero Knight** (`hero-knight`, keys `hk_*`): 150×90 frames, 180×140 moves. Battle-Worn damage stages (worn1–3), Samurai + Akatsuki costumes. Unarmed `_u` sheets.
- **Test fighters** (`TEST_ROSTER` in `roster.js`, played from Trinkets > TEST FIGHTERS, never on the select grid):
  **NU** (`nu`, keys `nu_*`, art `tools/sprites/nu_draw.py` + `nu_moves.py`) and **AERO** (`aero`, keys `aero_*`, `aero_draw.py` +
  `aero_moves.py`; his FULL AERO form - permanent until KO'd, floating (`def.float`), attacking with a golden spear (spear animations `k_*`) (part `spear`; `SPEAR` in aero.js grows his normals' reach and damage) - is `aero_king_*`, `aero_king_draw.py`, def `AERO_FULL`). 64×64 base frames, 112×104 moves.
  **WHAT ONCE WAS** (`what-once-was`, keys `wow_*`, art `tools/sprites/what_once_was_draw.py` + `what_once_was_moves.py`, same rig as NU):
  a deformed Backrooms entity with a CRT TV head (screen layers `scr_*` picked per pose). MISSING Poster, Channel Surf side-B, OUT OF
  BODY up-B, Wrong Door down-B, LEVEL 0 limit (the Bacteria chase). Unique mechanic: `def.signal` meter -> when full it
  transforms into a random MODE (`def.modes`: SEE / INCOMING / SMILE) until KO'd; each mode has a passive and swaps side-B for a command
  grab (states `see_side/see_hold`, ...; the victim is in state `seized`). The mode's face is drawn live over the TV: `wowScreens.js`
  (generated) says where the screen is in every frame, `mode_screens.png` holds the animated faces. Costumes FRUTIGER / ROOT ACCESS /
  RONIN have their own drawn sheets (`costumeSheets`, style `wowAero` / `wowHack` / `wowRonin`) and effects (`vfx.wow`, HALLS/FXS).
  **Its sheets are all drawn WITHOUT the head**: the game draws the TV (`heads.png`, a row per costume) at the spot `wowScreens.js`
  gives for the current frame (`drawHead`). OUT OF BODY launches the TV (the player flies as it); where it lands a new body grows
  (`def.bodies`: self / suit / swat / doctor, sheets in `body-*/`, `bodySheets`) and keeps it until the next up-B. Menus use
  `menuSheets` (drawn with the head).
- Every fighter has a taunt (`def.taunt`, 1 key / stick click); training hotkeys are 2–7.

## How to add things
**A move / rebalance:** edit the `moves` object in the fighter's def. Hit format:
`{ from, to, box: [x, y, w, h], dmg, angle, base, growth, stun? }` — box relative to feet, facing right.
**A fighter / stage / item:** follow the skill in `.claude/skills/` (full wire-up checklist).
**Art/sound:** generator scripts in `tools/` (Python) write into `public/assets/`; rerun the script rather than editing PNGs.

## Testing: `npm run sim`
Headless all-CPU matches, ~0.3 s per minute of game time (`tools/sim/sim.mjs`). Needs Chrome or Edge installed.
- `npm run sim -- --smoke` → every stage, fighter and costume. Run after any gameplay change. Exit code 1 on errors.
- `npm run sim -- --fighters soul-summoner,mr-wake --stage sky-sanctum --matches 10` → balance comparisons
- **Refactor check**: same seed = identical match. Save `npm run sim -- --smoke --json` before the change and
  compare it after (ignore `simMs`). Any difference means behaviour changed.
- Keep game logic on `Math.random()` (the sim seeds it) and frame counts, never `Date.now()` or real time.
- The sim can't judge looks or feel: ask Mason to playtest anything visual.

## Working conventions
- Keep fighter files data-only; behaviour goes in Fighter.js / entities.js.
- Comment style: short plain-English line above each tunable explaining what it does in game terms.
- Commit messages: short, describe the player-visible change.
- Don't touch generated files (`*Moves.js` marked "do not edit by hand").
